Cluster

Cluster WireGuard

Rode o WireGuard em vários servidores e gerencie todos a partir de um único painel.

Como funciona

O servidor principal é onde você gerencia tudo: instâncias, peers, firewall, DNS e aplicações do App Gateway. Os nós workers rodam um agente leve que se conecta ao servidor principal, recebe a configuração e a aplica localmente. Os workers não têm painel nem banco de dados próprios: um nó novo fica pronto em poucos minutos.

1 O worker se conecta

O agente se autentica com o seu token e chama o servidor principal por HTTPS. Os workers só fazem conexões de saída.

2 Sincronização

As configurações de WireGuard, firewall, DNS e App Gateway são enviadas em seções separadas. Só o que mudou é aplicado de novo.

3 Status

Cada worker envia ao servidor principal o status do WireGuard, o tráfego dos peers, os serviços e os certificados.

4 Visão única

A lista de peers mostra em qual servidor cada peer está conectado, em todo o cluster.

Modos do cluster

Espelho
Todos os nós rodam todas as instâncias WireGuard com os mesmos peers. O usuário escolhe o servidor ao baixar a configuração ou abrir um convite de VPN, então o mesmo peer pode se conectar por qualquer nó. Útil para redundância e para servidores em regiões diferentes.
Distribuído
Cada instância WireGuard roda em um único servidor, escolhido nas configurações da instância (por padrão, o servidor principal). Útil para espalhar instâncias entre locais ou manter cada rede no seu próprio local.

Servidor principal só como gerenciador

No modo espelho, o WireGuard pode ser desabilitado no servidor principal. Ele para as suas interfaces WireGuard, deixa de ser oferecido como servidor para os peers e publica apenas o painel do WireGuard WebAdmin, enquanto os workers continuam atendendo todos os peers.

Antes de desabilitar, garanta que você consegue acessar o painel sem a VPN do servidor principal.

App Gateway nos workers

Os workers instalados com o App Gateway também publicam as suas aplicações Zero Trust. Cada aplicação escolhe onde é servida: no servidor principal, em todos os workers ou em workers selecionados.

Os certificados são emitidos pelo servidor principal e distribuídos aos workers, por isso as aplicações publicadas pelos workers precisam usar validação DNS ou certificados autoassinados.

Adicionando um worker

01
Habilite o cluster

Nas configurações do cluster no servidor principal, habilite o cluster e escolha o modo. O cluster usa o cache de status do WireGuard, que vem habilitado por padrão.

02
Crie o worker

Adicione um worker com um nome e o hostname que os clientes usam para alcançá-lo: ele vira o endpoint das configurações de peer baixadas para esse servidor. A página do worker mostra o token e os comandos de instalação.

03
Baixe o arquivo compose no servidor do worker
mkdir wireguard_webadmin_node && cd wireguard_webadmin_node
wget -O docker-compose.yml \
  https://raw.githubusercontent.com/eduardogsilva/wireguard_webadmin/main/cluster_node.yml
mkdir wireguard_webadmin_node && cd wireguard_webadmin_node
wget -O docker-compose.yml \
  https://raw.githubusercontent.com/eduardogsilva/wireguard_webadmin/main/cluster_node-gateway.yml
04
Crie o arquivo .env
MASTER_SERVER_ADDRESS=https://vpn.example.com
TOKEN=token-exibido-na-pagina-do-worker
TIMEZONE=America/Sao_Paulo
05
Suba o worker
docker compose up -d

Requisitos de rede

  • Os workers precisam alcançar o servidor principal por HTTPS. Se o App Gateway protege o painel do servidor principal, adicione uma rota para /api/cluster/ com uma política pública.
  • Publique as portas do WireGuard (51820-51839/udp) em cada worker e, com o App Gateway, as portas 80 e 443.

Atualizando um worker

Rode docker compose pull e depois docker compose up -d. Para trocar entre Somente VPN e VPN e App Gateway, baixe o outro arquivo compose no mesmo diretório e rode docker compose up -d --remove-orphans. Os dados do worker são mantidos.

Monitoramento e automação

A página do worker mostra quando ele foi visto pela última vez, a versão do agente, o estado de sincronização de cada seção, os serviços e os certificados.

  • Desabilite um worker e ele desliga as suas interfaces WireGuard até ser habilitado novamente.
  • Bloqueio por IP só aceita o worker a partir de um endereço IP fixo.
  • A API v2 permite que ferramentas externas habilitem e desabilitem workers e o WireGuard do servidor principal. A chave de API precisa da permissão de gerenciamento do cluster.

Continua sendo uma única stack. O cluster é opcional: um servidor sozinho continua funcionando exatamente como antes, e os workers podem ser adicionados a qualquer momento.
