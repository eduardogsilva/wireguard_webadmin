Cluster

WireGuard-Cluster

Betreiben Sie WireGuard auf mehreren Servern und verwalten Sie alle über ein einziges Panel.

So funktioniert es

Auf dem primären Server verwalten Sie alles: Instanzen, Peers, Firewall, DNS und App-Gateway-Anwendungen. Worker-Knoten betreiben einen schlanken Agenten, der sich mit dem primären Server verbindet, die Konfiguration empfängt und lokal anwendet. Worker haben weder ein eigenes Panel noch eine eigene Datenbank: Ein neuer Knoten ist in wenigen Minuten bereit.

1 Worker verbindet sich

Der Agent authentifiziert sich mit seinem Token und ruft den primären Server über HTTPS auf. Worker bauen nur ausgehende Verbindungen auf.

2 Synchronisierung

WireGuard-, Firewall-, DNS- und App-Gateway-Einstellungen werden in getrennten Abschnitten übertragen. Nur Geändertes wird erneut angewendet.

3 Statusmeldung

Jeder Worker meldet dem primären Server den WireGuard-Status, den Peer-Traffic, die Dienste und die Zertifikate.

4 Eine Ansicht

Die Peer-Liste zeigt, auf welchem Server jeder Peer verbunden ist, im gesamten Cluster.

Cluster-Modi

Spiegelmodus
Jeder Knoten betreibt jede WireGuard-Instanz mit denselben Peers. Benutzer wählen den Server beim Herunterladen der Konfiguration oder beim Öffnen einer VPN-Einladung, sodass derselbe Peer sich über jeden Knoten verbinden kann. Nützlich für Redundanz und für Server in verschiedenen Regionen.
Verteilt
Jede WireGuard-Instanz läuft auf genau einem Server, der in den Instanzeinstellungen gewählt wird (standardmäßig der primäre Server). Nützlich, um Instanzen auf Standorte zu verteilen oder jedes Netz an seinem eigenen Standort zu halten.

Primärer Server nur als Verwaltung

Im Spiegelmodus lässt sich WireGuard auf dem primären Server deaktivieren. Er stoppt seine WireGuard-Schnittstellen, wird Peers nicht mehr als Server angeboten und veröffentlicht nur noch das WireGuard-WebAdmin-Panel, während die Worker weiterhin alle Peers bedienen.

Vor dem Deaktivieren sicherstellen, dass Sie das Panel ohne das VPN des primären Servers erreichen.

App Gateway auf Worker-Knoten

Mit dem App Gateway installierte Worker veröffentlichen auch Ihre Zero-Trust-Anwendungen. Jede Anwendung legt fest, wo sie bereitgestellt wird: auf dem primären Server, auf allen Workern oder auf ausgewählten Workern.

Zertifikate werden vom primären Server ausgestellt und an die Worker verteilt. Von Workern veröffentlichte Anwendungen müssen daher DNS-Validierung oder selbstsignierte Zertifikate verwenden.

Einen Worker hinzufügen

01
Cluster aktivieren

Aktivieren Sie in den Cluster-Einstellungen des primären Servers den Cluster und wählen Sie den Modus. Der Cluster nutzt den WireGuard-Status-Cache, der standardmäßig aktiviert ist.

02
Worker anlegen

Legen Sie einen Worker mit einem Namen und dem Hostnamen an, über den Clients ihn erreichen: Er wird zum Endpoint der für diesen Server heruntergeladenen Peer-Konfigurationen. Die Worker-Seite zeigt den Token und die Installationsbefehle.

03
Compose-Datei auf dem Worker-Server abrufen
mkdir wireguard_webadmin_node && cd wireguard_webadmin_node
wget -O docker-compose.yml \
  https://raw.githubusercontent.com/eduardogsilva/wireguard_webadmin/main/cluster_node.yml
mkdir wireguard_webadmin_node && cd wireguard_webadmin_node
wget -O docker-compose.yml \
  https://raw.githubusercontent.com/eduardogsilva/wireguard_webadmin/main/cluster_node-gateway.yml
04
.env-Datei anlegen
MASTER_SERVER_ADDRESS=https://vpn.example.com
TOKEN=token-von-der-worker-seite
TIMEZONE=Europe/Berlin
05
Worker starten
docker compose up -d

Netzwerkanforderungen

  • Worker müssen den primären Server über HTTPS erreichen. Schützt das App Gateway das Panel des primären Servers, fügen Sie eine Route für /api/cluster/ mit einer öffentlichen Richtlinie hinzu.
  • Geben Sie auf jedem Worker die WireGuard-Ports (51820-51839/udp) frei und, mit dem App Gateway, die Ports 80 und 443.

Einen Worker aktualisieren

Führen Sie docker compose pull und danach docker compose up -d aus. Um zwischen Nur VPN und VPN und App Gateway zu wechseln, laden Sie die andere Compose-Datei in dasselbe Verzeichnis und führen docker compose up -d --remove-orphans aus. Die Worker-Daten bleiben erhalten.

Überwachung und Automatisierung

Die Worker-Seite zeigt, wann der Worker zuletzt gesehen wurde, seine Agent-Version, den Synchronisierungsstatus jedes Abschnitts, seine Dienste und seine Zertifikate.

  • Deaktivieren Sie einen Worker, und er fährt seine WireGuard-Schnittstellen herunter, bis er wieder aktiviert wird.
  • Die IP-Sperre akzeptiert den Worker nur von einer festen IP-Adresse.
  • Die API v2 erlaubt externen Werkzeugen, Worker und WireGuard auf dem primären Server zu aktivieren und zu deaktivieren. Der API-Schlüssel benötigt die Berechtigung zur Cluster-Verwaltung.

Weiterhin ein einziger Stack. Der Cluster ist optional: Ein einzelner Server funktioniert genau wie bisher, und Worker lassen sich jederzeit hinzufügen.
