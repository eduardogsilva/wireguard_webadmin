Clúster

Clúster WireGuard

Ejecuta WireGuard en varios servidores y gestiónalos todos desde un único panel.

Cómo funciona

El servidor principal es donde gestionas todo: instancias, peers, firewall, DNS y aplicaciones del App Gateway. Los nodos workers ejecutan un agente ligero que se conecta al servidor principal, recibe la configuración y la aplica localmente. Los workers no tienen panel ni base de datos propios: un nodo nuevo está listo en pocos minutos.

1 El worker se conecta

El agente se autentica con su token y llama al servidor principal por HTTPS. Los workers solo hacen conexiones salientes.

2 Sincronización

La configuración de WireGuard, firewall, DNS y App Gateway se envía en secciones separadas. Solo se vuelve a aplicar lo que cambió.

3 Estado

Cada worker envía al servidor principal el estado de WireGuard, el tráfico de los peers, los servicios y los certificados.

4 Una sola vista

La lista de peers muestra en qué servidor está conectado cada peer, en todo el clúster.

Modos del clúster

Espejo
Todos los nodos ejecutan todas las instancias WireGuard con los mismos peers. El usuario elige el servidor al descargar la configuración o abrir una invitación VPN, así que el mismo peer puede conectarse por cualquier nodo. Útil para redundancia y para servidores en distintas regiones.
Distribuido
Cada instancia WireGuard se ejecuta en un único servidor, elegido en la configuración de la instancia (por defecto, el servidor principal). Útil para repartir instancias entre sedes o mantener cada red en su propia ubicación.

El servidor principal solo como gestor

En modo espejo, WireGuard se puede deshabilitar en el servidor principal. Este detiene sus interfaces WireGuard, deja de ofrecerse como servidor para los peers y solo publica el panel de WireGuard WebAdmin, mientras los workers siguen atendiendo a todos los peers.

Antes de deshabilitarlo, asegúrate de poder acceder al panel sin la VPN del servidor principal.

App Gateway en los workers

Los workers instalados con el App Gateway también publican tus aplicaciones Zero Trust. Cada aplicación elige dónde se sirve: en el servidor principal, en todos los workers o en workers seleccionados.

Los certificados los emite el servidor principal y se distribuyen a los workers, por lo que las aplicaciones publicadas por workers deben usar validación DNS o certificados autofirmados.

Agregar un worker

01
Habilitar el clúster

En la configuración del clúster del servidor principal, habilita el clúster y elige el modo. El clúster usa la caché de estado de WireGuard, habilitada por defecto.

02
Crear el worker

Agrega un worker con un nombre y el hostname que usan los clientes para alcanzarlo: será el endpoint de las configuraciones de peer descargadas para ese servidor. La página del worker muestra su token y los comandos de instalación.

03
Descargar el archivo compose en el servidor del worker
mkdir wireguard_webadmin_node && cd wireguard_webadmin_node
wget -O docker-compose.yml \
  https://raw.githubusercontent.com/eduardogsilva/wireguard_webadmin/main/cluster_node.yml
mkdir wireguard_webadmin_node && cd wireguard_webadmin_node
wget -O docker-compose.yml \
  https://raw.githubusercontent.com/eduardogsilva/wireguard_webadmin/main/cluster_node-gateway.yml
04
Crear el archivo .env
MASTER_SERVER_ADDRESS=https://vpn.example.com
TOKEN=token-mostrado-en-la-pagina-del-worker
TIMEZONE=America/Sao_Paulo
05
Iniciar el worker
docker compose up -d

Requisitos de red

  • Los workers deben alcanzar el servidor principal por HTTPS. Si el App Gateway protege el panel del servidor principal, agrega una ruta para /api/cluster/ con una política pública.
  • Publica los puertos de WireGuard (51820-51839/udp) en cada worker y, con el App Gateway, los puertos 80 y 443.

Actualizar un worker

Ejecuta docker compose pull y luego docker compose up -d. Para cambiar entre Solo VPN y VPN y App Gateway, descarga el otro archivo compose en el mismo directorio y ejecuta docker compose up -d --remove-orphans. Los datos del worker se conservan.

Monitoreo y automatización

La página del worker muestra cuándo se vio por última vez, la versión del agente, el estado de sincronización de cada sección, los servicios y los certificados.

  • Deshabilita un worker y este apaga sus interfaces WireGuard hasta que se habilite de nuevo.
  • El bloqueo por IP solo acepta el worker desde una dirección IP fija.
  • La API v2 permite que herramientas externas habiliten y deshabiliten workers y el WireGuard del servidor principal. La clave de API necesita el permiso de gestión del clúster.

Sigue siendo un solo stack. El clúster es opcional: un servidor solo sigue funcionando exactamente igual, y los workers se pueden agregar en cualquier momento.
